# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

EX_P02 is the codebase for **memex**, a personal working-memory system built as a React web app with a Supabase backend. The app wears one design, **Memory Cards** (`design/memory-cards/`, the only look since 2026-11-17): a top bar (Journal · Cards · Tasks, Inbox, account) over one scrolling column. The Journal is home; **Cards** (the Library, `/library`) shows every note, link, task and jot as a chunky card under a hero, one save/search field and a row of space pills, with layouts, filters, sort and saved views behind its ••• View panel. Notes/links/tasks are data primitives; spaces are the cross-cutting contexts that filter and compose them (see `VISION.md`). The previous Pastel Sky design (sidebar, frosted stack, filter chips) is kept only as the tag `classic-design-final` (branch `archive/classic-design`).

## Safety rules for agents

memex holds Ryan's real data in one production Supabase project; there is no staging copy. These rules apply to every agent and every task, whatever the permission mode:

1. **Back up before any migration.** Run `scripts/backup-supabase.sh` and confirm it finished (folder path + row counts) before `supabase db push` or any SQL against production. Restore steps: `docs/backups.md`.
2. **Only additive migrations without Ryan's sign-off.** New tables, columns, indexes and policies are fine. Dropping or renaming anything, changing a column's type, rewriting rows, or tightening a constraint that existing rows might break needs Ryan's explicit OK in the conversation first.
3. **Never delete or bulk-modify Ryan's data unless he asks.** That covers the app, scripts, the SQL editor and the API. Backfills and data fixes run with `--dry-run` first, and the real run needs his go-ahead.
4. **Never commit secrets.** Keys, tokens and passwords live in gitignored env files (`.env`, `.env.*`, `.dev.vars`) or `wrangler secret`, never in code, docs or commit messages. Inspect env files by variable name only; don't print values. CI runs gitleaks on every push and PR; run `gitleaks git --redact --log-opts="--all" .` locally when unsure (`SETUP.md` → “Secrets and backups”).
5. **Label any test data clearly.** Anything an agent creates in production (jots, links, notes, tasks, spaces, tokens) starts with `[test]` in its title or text so Ryan can find and remove it, and the agent says what it created in its report. Prefer a local Supabase stack for anything heavier.

## Architecture Overview

### Technology Stack
- **Frontend**: React 19 + TypeScript + Vite
- **Styling**: **Memory Cards** — tokens in `src/styles/cards/tokens.css` (`--mc-*`), the kit in `src/styles/cards/kit.css` (`.mc-*`) and per-page files beside it, imported once by `src/main.tsx` after the base styles (`src/index.css`, `src/styles/components.css`, `stream.css`, `library.css`, `journal.css`, which still carry the Pastel Sky tokens the shared Journal / List / Table / note-editor classes use)
- **Backend**: Supabase (PostgreSQL + Auth + RLS)
- **State Management**: Zustand global store
- **Data Fetching**: React Query (TanStack Query)
- **Routing**: React Router v7
- **Shared logic**: `packages/core` (`@memex/core`, npm workspace) — see Core Structure

### Core Structure
- **`packages/core` (`@memex/core`)**: the logic the web app, the Expo app (Phase 6) and memex-api's MCP server share (ROADMAP §3.1). Pure TS: no React, no DOM, no Supabase client; source-only (no build step). Domain types (`types.ts`), item types, the Journal model (`journal/feed.ts`) and filing suggester (`journal/filer.ts`), composer syntax (`composer.ts`), the Library's filters (`stream/filters.ts`) and `StreamItem` (`stream/items.ts`), the source registry (`sources.ts`), URL/markdown/link/time helpers, and design tokens (`tokens/`: canvas swatches, OKLCH maths, space colours, Pastel Sky constants). Its README lists the public API
- **Data access**: the `Repository` interface (`packages/core/src/repository.ts`) covers everything the app reads and writes. `@memex/core/supabase` holds the v1 adapter (`createSupabaseRepository`) and `createMemexClient` (one Supabase client factory with injectable auth storage; decision 20: web and Expo both use it, RLS protects rows). The app builds one repository in `src/data/repository.ts`; hooks in `src/hooks/` wrap it in React Query, and `SessionContext` / the auth pages use `repository.auth`. Nothing else in `src/` imports supabase-js
- **Authentication**: Supabase Auth (email/password + GitHub OAuth); session flows through `SessionProvider` / `useSession` (`src/context/SessionContext.tsx`); `AuthProtectedRoute` guards authenticated routes
- **Journal (home, `/`)**: `src/pages/JournalPage.tsx` (2026-10-25, ROADMAP Phase 1) — every jot, link, note and task in one chronological feed, newest at the bottom, composer below. Model in `@memex/core` (`journal/feed.ts`: entries, day separators, runs of saves from one platform; `journal/filer.ts`: the filing suggester and the Inbox), data via `src/hooks/useJournal.ts`, renderers in `src/components/journal/` (Memory Cards d23: jots are bubbles, links and notes are memory cards with their label strip, tasks chunky rows, platform saves with pictures stay big as galleries) on one paper column under a “Today” hero. Composer syntax in `@memex/core` (`composer.ts`): plain text → jot, lone URL → link, `[] ` → task, ⌘/Ctrl↵ → note, `@Space` files it (picker on `@`). Filing (decision 13): space chips, a dashed one-press suggestion chip with its reason, “File to…” in hover actions. The Inbox (agents' proposals and recent unfiled items with a suggestion) is its own page, `/inbox` (`src/pages/InboxPage.tsx`), with its count on the top bar; an old `/?inbox=1` link redirects there. Decision 17B (2026-11-01, `docs/journal-17b.md`): the feed is a 760px notebook page with the title aligned over it; quick jots stack into one thought (core `journal/jots.ts`: `groupJots`); a jot edits in place (menu Edit or double-click, Undo), moves between spaces through “File to…”/drag (`repository.jots.update`, `hooks/useMoveJots.ts`), and is found in ⌘K (`?jot=<id>` scrolls to it). `RootRoute` renders the Journal inside `MemexShell` when signed in, the landing page otherwise
- **Library (“Cards”)**: `src/pages/StreamPage.tsx`, mounted at `/library` (one space's grid is `/library?space=<id>`). A hero with the count, one field that searches as you type and saves on Enter or + (`components/cards/CaptureSheet.tsx`), the space pills (`components/cards/SpacePillRow.tsx`: All, your spaces in your order, as many as fit the window, More for the rest and Edit spaces…, + for a new space; pills are drop targets; a compact copy sticks to the top once they scroll away, `StickyBar`, and every card drag opens the drop tray, `DropTray`; `docs/spaces-row.md`), then the grid of memory cards (`components/cards/cards.tsx`: link, picture, note, task and jot cards; jots join the grid only in the plain date-ordered view, `utils/cardsGrid.ts`). A card opens as a centred sheet (`components/cards/OpenCardSheet.tsx`, `?link=`), a note in the editor (`?note=`). The ••• View panel (`components/cards/ViewPanel.tsx`) holds decision 15A (`docs/library-views.md`): Grid · List · Table, Show (type) and From (source) filters, Unfiled, Sort, saved views (save, rename, update, delete), Select cards and Open space page; view logic, sort and columns live in `@memex/core` (`stream/views.ts`, `stream/sort.ts`, `stream/table.ts`), saved views in `repository.views` (`useSavedViews`). The Table is `components/library/LibraryTable.tsx` (sortable columns, row keys ↑/↓/Enter/X/Delete), List rows `components/stream/StreamRow.tsx`. The grid is virtualized (2026-11-12, `docs/library-grid-performance.md`): `MasonryLayout` mounts only the cards near the viewport; geometry in `src/utils/masonry.ts`, estimates in `utils/memoryCardEstimates.ts`, picture ratios in `utils/imageRatios.ts` (a card changes size only while below the viewport). Anything that needs every card on screen (⌘A, Shift-click ranges) reads the grid's full order, never the DOM. `/home`, `/links`, `/notes`, `/spaces`, `/project/:id` and `/protected` redirect into the Library, carrying their query (`src/router/LegacyModuleRedirect.tsx`)
- **Space page (`/spaces/:spaceId`)**: `src/pages/SpacePage.tsx` (decision 14B, Memory Cards d03, `docs/space-page.md`) — a band in the space's colour with its name, count and summary, then its board (`components/space/SpaceBoard.tsx`: Pinned · Open tasks (the Tasks view's `TaskRow`s) · Saves · Notes; model `spaceBoard` in `@memex/core` `journal/space.ts`) or, behind the Board · Journal toggle (`?show=journal`), the space's own Journal (the home Journal's `components/journal/JournalFeed.tsx`, scoped with `entriesInSpace`; the composer files into the space unless you `@` another, `withDefaultSpace`). Its ••• has Space details (rename, colour, delete), Open in Cards and Tasks in this space
- **Tasks (`/tasks`)**: `src/pages/TasksPage.tsx` (2026-11-01, `docs/tasks-view.md`) — open tasks across every space, grouped by space (default) or due date (`?group=date`), Space filter (`?space=`), Done list (`?done=1`), tick with Undo (the row holds a beat, then moves to Done), due dates (row chip opens the native picker; menu has Today/Tomorrow/Next week), rename, file/unfile, delete with Undo, add field on the composer's syntax (`components/tasks/TaskComposer.tsx`, `@Space` files). Rows and their actions are shared with the space board: `components/tasks/TaskRow.tsx`, `components/tasks/taskList.ts` (keys, focus, `TaskRowHandlers`), `hooks/useTaskActions.ts`; groups are colour bands (d27). Model in `@memex/core` `tasks/tasks.ts`. Keys: N add, ↑/↓ rows, Space tick, Enter rename, Delete delete. `/tasks` was a Library redirect before
- **Go to (⌘/Ctrl K)**: `src/components/GoToPalette.tsx`, mounted by `MemexShell` on every signed-in page: Journal, Library, Tasks, Inbox (when waiting), spaces, and jots once you type two letters (core `searchJots`; Enter opens `/?jot=<id>`). On Cards, “/” focuses the save/search field
- **Drag to a space**: any element with `data-item-key` (cards, list/Table rows, task rows, Journal entries) spreads `dragAttrs(key, title)` (`src/utils/itemDrag.ts`); one document listener (`hooks/useItemDragSource.ts`, mounted by `MemexShell`) turns a drag into a drag of item keys (the whole selection when the item is selected) with a small paper ghost; space pills accept the drop and file through `useAddToSpace` (the same path as the selection bar). Every filing (drag, selection bar, sidebar, “File to…”) toasts with Undo, which takes back out only what that call filed. “File to…” on a space that's already ticked takes the item out (`hooks/useRemoveFromSpace.ts`, Undo puts it back). Keyboard/menu alternatives: the selection bar's Move to…, “File to…” in the Journal, the Tasks row menu, + Space on an open card or note
- **Filtering model**: the space pills choose a space; the View panel's Show (Links · Notes · Tasks), From (X · Pinterest · YouTube · Web), Unfiled and Sort do the rest (logic in `@memex/core` `stream/filters.ts`, `stream/views.ts`, `stream/sort.ts`). Tags stay hidden (`SHOW_TAGS_UI = false`), though `?tags=` / `?untagged=1` still filter. Empty selection = show all; all live in the URL (`?type=`, `?tags=`, `?untagged=1`, `?source=`, `?space=unfiled,<id>`, `?sort=field:dir`, `?view=grid|list|table`); the open note is `?note=<id>`, the open card `?link=<id>`. A capture while one space is chosen is filed there
- **Multi-select**: selection state lives in the Zustand store. ⌘/Ctrl-click (or Shift-click for a range) any card or row, ⌘/Ctrl A for everything on screen, or View panel → Select cards; Esc exits. A floating selection bar (`src/components/cards/SelectionBar.tsx`) shows the count (plus how many the filters hide; selection survives filter/search changes, not space changes), Move to… (the space sheet, `components/cards/MoveSheet.tsx`), Delete (one Undo for the batch) and ✕. Space pills stay drop and add-to targets (`useAddToSpace`). Cards and rows carry `data-item-key` so the page resolves modifier and range clicks in display order
- **Canvas theming**: the user's OKLCH canvas swatch (Settings → Canvas) tints the page background (`--mc-bg` mixes in `--bookmark-canvas-base`) and drives the base styles' accent roles (`--color-1`, `--cte-accent-text`, `--color-1-ink`) at runtime (`src/utils/canvasColor.ts` applies it; swatches and OKLCH maths in `@memex/core` `tokens/`); dark mode via `data-theme`; the heading font (Nunito or IBM Plex, Settings → Font) via `data-cards-font` (`src/utils/cardsFont.ts`)

### Data Schema (current)
All tables user-scoped via RLS:
- **links** — URL + metadata (title, description, favicon, preview image), global pin (`is_super_favorite`, its place `pin_position`; the Pinned launcher outside a space, `docs/pinned-sites.md`), ordering, and capture provenance: `source` (platform `x` · `pinterest` · `youtube` · `web`, written by memex-api since 2026-11-01; older captures hold a tag like `x:bookmark`, read with `parseSourceTag`; NULL = saved in the app), `source_id`, `lists` (`bookmarked` · `saved` · `liked`), `captured_by`, `captured_client`, `url_key` (migrations `20261018120000_add_link_source.sql`, `20261101120000_add_capture_provenance.sql`; unique on `(user_id, source, source_id)`). Capture/dedupe rules: `@memex/core/capture`
- **tags** / **link_tags** / **note_tags** / **task_tags** — shared tag vocabulary, many-to-many with each primitive
- **self_messages** — "Notes to Self": short chat-style messages, `profile_id` NULL = Home feed, otherwise one feed per space; `legacy_id` marks rows migrated from the legacy app (migration `20260907150000_add_self_messages.sql`, script `scripts/migrate-self-messages.mjs`)
- **profiles** / **profile_links** / **profile_notes** / **profile_tasks** — spaces (still named profiles in the DB; `position` orders them, `hidden` keeps one out of the pill rows, migration `20261119120000_add_space_order.sql`, `docs/spaces-row.md`; colours stay by creation date) and their membership joins; `profile_links.is_super_favorite` pins a link in that space's launcher and board, `pin_position` is its place (migrations `20260907120000_add_profile_link_super_favorite.sql`, `20261118120000_add_pin_positions.sql`)

### Conventions
- New features integrate with existing auth, routing, and React Query patterns; add providers in `src/Providers.tsx`
- Any new item type renders as a `MemoryCard` (picture · title · excerpt · label strip; `components/cards/MemoryCard.tsx`, wrappers in `cards.tsx`) and joins the `StreamItem` union; don't invent a second card or list anatomy.
